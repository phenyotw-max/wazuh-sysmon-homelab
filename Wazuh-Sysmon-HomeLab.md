01- Architecture.md:
Overview: 
	**Centralized Log Collection & Analysis (Wazuh SIEM Server):** Acts as the brain of the operation. It ingests, aggregates, and analyzes log data in real-time from all connected machines, matching events against threat intelligence rules and the MITRE ATT&CK framework.
	**Deep Endpoint Visibility (Sysmon):** Installed on the target VMs, Microsoft System Monitor (Sysmon) logs granular system activities—such as process creations, network connections, file modifications, and registry changes—that standard Windows logs often miss
	**Attack Simulation & Threat Testing (The Attacker VM):** The third VM(Kali-Purple) acts as a malicious actor (e.g., running Kali Linux or an attack framework) to launch real-world exploits, lateral movement, or privilege escalation attempts against the other VMs.
	**Detection & Validation:** As the attacker VM strikes, Sysmon captures the granular footprint of the attack on the victims, streams those logs to the Wazuh server, and triggers security alerts. This allows you to observe how attacks manifest and test whether your SIEM rules successfully catch them.
Virtualization:
	All the Virtual Machines in this project where run on VMware Workstation Pro.

Data Flow Description:Microsoft System Monitor (Sysmon) captures low-level endpoint telemetry and logs it locally, where the local Wazuh Agent reads and securely streams these events to the Wazuh Server Manager. The Manager then processes and correlates the incoming logs against detection rules before forwarding them to the Wazuh Indexer, making the telemetry instantly searchable and visualizable on the Wazuh Dashboard.

02- Configuration .md:
	Wazuh Server Deployment:The Wazuh server was deployed using the official automated installation script from the official Wazuh documentation, which handles the setup for the Wazuh manager, indexer, and dashboard components. Once the installation completed, the Web UI was accessed by navigating to the server's IP address via HTTPS Port 443 in a web browser and logging in using the administrative credentials generated by the script.
		1. Sysmon Installation & Baseline Configuration
			Sysmon (System Monitor) was deployed on the Windows 10 endpoint to provide deep, kernel-level telemetry that standard Windows event logs overlook (such as process creation, network connections, and file creation time changes).
			Installation Method: Sysmon was installed using the official Microsoft Sysinternals `Sysmon64.exe` binary paired with a hardened baseline configuration file (such as **SwiftOnSecurity’s `sysmonconfig.xml`**).
    
- **Execution Command:**
    PowerShell
    ```
    .\Sysmon64.exe -accepteula -i sysmonconfig.xml
    ```
- **Purpose:** The baseline configuration filters out noisy, benign background system events while logging high-value security telemetry, which is then parsed by the local Wazuh agent and forwarded to the Wazuh manager.

2. Custom Wazuh Rules Configuration (SSH Brute-Force & Endpoint Detections):

To enhance the lab's detection capabilities beyond default rules, custom correlation rules were added to the Wazuh server's local rules file (`/var/ossec/etc/local_rules.xml`). These rules detect repeated authentication failures and map them to the **MITRE ATT&CK** framework.

#### **Detecting Multiple SSH Failures & Brute-Force (Linux Endpoints)**

Two custom rules were implemented to flag suspicious authentication patterns from the same source IP:

- **Rule `100101`:** Monitors for multiple SSH login failures, triggering at a **frequency of 3 failures within a 120-second timeframe** (`same_source_ip`) by correlating base SSH failure signatures (matching SID `5760`).
    
    - _MITRE ATT&CK:_ **T1110 (Brute Force)**
        
- **Rule `100002`:** A higher-threshold custom rule designed to catch aggressive brute-force attacks (`frequency="4" timeframe="120"`), mapping against authentication failure baseline SIDs (`5710`) to raise a high-severity alert (`level="10"`) specifying the attacker's source IP (`$(srcip)`).
    
    - _MITRE ATT&CK:_ **T1110.001 (Password Guessing)**
#### **Additional Custom Detections Implemented**

- **Rule `100001` (PowerShell Execution):** Detects PowerShell process spawning on Windows endpoints by filtering Sysmon/Windows event IDs (matching SID `61603` with regex `powershell\.exe`), mapping to command-line execution.
    
    - _MITRE ATT&CK:_ **T1059.001 (Command and Scripting Interpreter: PowerShell)**
        
- **Rule `100200` (Account Security):** Flags instances where the built-in Windows Guest account is enabled.
    
    - _MITRE ATT&CK:_ **T1078 (Valid Accounts)**
During the lab configuration and threat monitoring, focus was placed on several key **Sysmon Event IDs** that capture critical endpoint activity:

  

- **Event ID 1: Process Creation** — Tracks new processes executing on the system along with their full command-line arguments. This was leveraged in custom rule implementations to detect suspicious or administrative process execution, such as PowerShell spawning (`powershell.exe`).
    
      
    
- **Event ID 3: Network Connection** — Logs TCP/UDP connections initiated by processes, providing deep visibility into outbound network communications, potential command-and-control (C2) callbacks, or lateral movement across the network.
    
      
    
- **Event ID 11: File Creation** — Records when a file is created or overwritten, which is essential for identifying dropped malware payloads, persistent scripts, or unauthorized modifications in sensitive system directories.

### 1. Linux Sysmon / Auditd Setup (Ubuntu VM)

To achieve deep endpoint visibility on the Ubuntu Linux endpoint (matching the telemetry depth of the Windows VM), **Sysmon for Linux** was deployed alongside the local Wazuh agent.

- **Installation:** Sysmon for Linux was installed by registering the official Microsoft software repository for Linux, installing the package (`sysmonforlinux`), and applying a baseline configuration XML file to filter and record system events.
    
- **Core Telemetry Captured:**
    
    - **Process Creation & Execution:** Tracks user commands, execution paths, and parent-child process chains.
        
    - **File System Activity:** Monitors critical system directories for unauthorized modifications or dropped payloads.
        
    - **Network Connections:** Logs outbound and inbound network sockets opened by system processes.
        

### 2. Wazuh Agent Registration

The Wazuh agent was deployed on both the Windows 10 and Ubuntu endpoints to stream system logs and telemetry back to the centralized manager.

- **Installation Method:**
    
    - **Ubuntu Endpoint:** Added the official Wazuh repository and GPG key, then installed the package via apt: `sudo apt install wazuh-agent`.
        
    - **Windows Endpoint:** Installed via the official Wazuh Windows MSI installer package.
        
- **Registration & Server Connection:**
    
    - Agents were registered to the Wazuh Manager by defining the manager's static IP address inside the agent's configuration file (`/etc/wazuh/ossec.conf` on Linux and `C:\Program Files (x86)\ossec-agent\ossec.conf` on Windows).
        
    - Secure communication and authentication were established using the manager's built-in enrollment/registration methods (such as utilizing the `agent-auth` tool or pre-shared keys) to ensure trusted communication between the endpoints and the Wazuh Server Manager.

03- Attack-Simulations-and-Detection.md:
## Proof of Work: Security Visibility & Testing

This section validates that the deployed security architecture—comprising the Wazuh SIEM, Sysmon, and custom correlation rules—successfully captures and alerts on adversarial techniques executed from the Kali Purple attacker node.

### 1. Testing Methodology

To verify that the security monitoring infrastructure and custom detection rules functioned correctly, the **Kali Purple VM** was utilized as an isolated offensive node. Real-world adversarial techniques—specifically credential access (brute-force) and suspicious process execution—were simulated against the Windows 10 and Ubuntu target endpoints. This ensured that telemetry flowed seamlessly from the endpoints, through the local Wazuh agents, and triggered the appropriate alerts on the Wazuh Dashboard manager.

### 2. Simulation Test Cases

#### **Test Case 1: SSH Brute-Force Attack (Target: Ubuntu Endpoint)**

- **Attack Action from Kali:** Executed a series of rapid, repeated failed SSH login attempts from the Kali Purple VM against the Ubuntu-Endpoint to simulate credential guessing.
    
- **Telemetry Triggered:** Linux system authentication logs (`/var/log/auth.log`) capturing repeated connection failures from the attacker's source IP.
    
- **Wazuh Rule ID & Alert Level:**
    
    - _Rule ID:_ **`100002`** (Custom Rule leveraging base authentication failure SIDs).
        
    - _Alert Level:_ **`10` (High Severity)**.
        
    - _MITRE ATT&CK Mapping:_ **T1110.001 (Credential Access: Password Guessing)**.
        
    - _Dashboard Output:_ Generated an alert specifying _“Custom Rule: Possible SSH Brute Force Attack Detected from [Kali IP]”_.
        

#### **Test Case 2: Suspicious Process Execution / PowerShell Spawning (Target: Windows 10 Endpoint)**

- **Attack Action from Kali / Endpoint Simulation:** Triggered administrative or simulated post-exploitation script execution that spawned a PowerShell instance on the Windows 10 target.
    
- **Sysmon Event ID Triggered:** **Sysmon Event ID 1 (Process Creation)**, capturing the exact image path (`powershell.exe`) and associated command-line arguments.
    
- **Wazuh Rule ID & Alert Level:**
    
    - _Rule ID:_ **`100001`** (Custom Rule parsing Sysmon process creation events).
        
    - _Alert Level:_ **`7` (Medium-High Severity)**.
        
    - _MITRE ATT&CK Mapping:_ **T1059.001 (Execution: PowerShell)**.
        
    - _Dashboard Output:_ Triggered an alert flagging unauthorized or monitored command-line interpreter execution on the Windows endpoint.
        

#### **Test Case 3: Network Connection & Port Activity (Target: Endpoints)**

- **Attack Action from Kali:** Performed targeted network enumeration and connection tests from Kali Purple against the internal network hosts.
    
- **Sysmon Event ID Triggered:** **Sysmon Event ID 3 (Network Connection Detected)**, logging socket creation, source/destination ports, and connection states.
    
- **Wazuh Rule ID & Alert Level:** Correlated against baseline network monitoring rules to track inbound reconnaissance and verify that endpoint agents are actively recording socket telemetry.
